### Deviation from plan §2.1/§9 "defined once"

The wire constants are defined once in `request_state_wire.rs`, but the codec keeps four copies:

- `VERSION_V1`/`VERSION_V2` as `&str` (`"rs1"`, `"rs2"`) next to `wire::VERSION_V1`/`V2: &[u8]`;
- the `255` inside `KID_TOO_LONG_MSG = "key id exceeds 255 UTF-8 bytes"` (= `wire::MAX_KID_LEN`);
- the private alias `MAX_ENCODED_KID_LEN = wire::MAX_ENCODED_KID_LEN` (an alias, not a literal);
- `prim::hmac_sha256` returns `[u8; 32]` rather than `[u8; TAG_LEN]`.

Why: deriving the `&str` tags with a const `str::from_utf8(wire::VERSION_V1)` initializer (or the
message with a const formatter) would give Charon a global whose body can panic (the `Result` of
`from_utf8` has to be unwrapped; not tried on this tree); plan §2.2 E04 and §9 B4 require the
`InvalidKeyring` messages to stay `&'static str` constants with the base text. The `prim` signature is
kept literally `[u8; 32]` so that the S08 axioms are stated against a stable signature.

Enforcement: `codec_constants_agree_with_wire` checks `VERSION_V1.as_bytes() == wire::VERSION_V1` and
`VERSION_V2.as_bytes() == wire::VERSION_V2` byte for byte and both against the base literals;
`MAX_ENCODED_KID_LEN == wire::MAX_ENCODED_KID_LEN == wire::b64_len(MAX_KID_LEN) == 340`;
`KID_TOO_LONG_MSG == format!("key id exceeds {MAX_KID_LEN} UTF-8 bytes")` and `==` the base text
(base `b9cfcfe` line 773), `KID_EMPTY_MSG` equal to the base text;
`RequestStateCodec::MIN_KEY_LENGTH == wire::MIN_KEY_LENGTH`; `prim::hmac_sha256(..)` bound to
`[u8; 32]` has length `wire::TAG_LEN`, and the decoded tag of a sealed rs1 and rs2 token has length
`wire::TAG_LEN`.

### Native-code axiom lock

Implemented in `scripts/lean-axiom-audit.lean`, `scripts/lean_guard.py` and
`scripts/lean-guard.sh` (`axioms`), with the new committed baseline
`formal/trusted/native-axioms.lock` (SHA-256 `e4fd1ef9…c689`):

- classification as SPQR `isNativeAxiom`: `Lean.trustCompiler` or a name component `_native`.
  Native-code axioms are taken out of the "disallowed axiom" check and out of the trusted-axiom
  list (also when declared in a trusted module) and handled separately;
- the audit accepts a reached native-code axiom only if it has no universe parameters and its
  statement is exactly `toStrSideCondition s` for a string literal `s`
  (`@Eq.{1} Bool (@decide (@LE.le.{0} Nat instLENat n Aeneas.Std.U32.max) (Nat.decLe n
  Aeneas.Std.U32.max)) true`, `n = ByteArray.size (String.toByteArray s)`, compared on the
  canonical text); any other fails the audit, listed or not. `lean_guard.py native-lock`
  repeats the form check on the canonical text;
- the audit prints the native-code axioms separately, with their literal, and writes them (name,
  declaring module, canonical statement) with the list of modules of the import closure;
- `native-lock` compares with the lock, lines `<name> <declaring module> sha256:<hex>` (the same
  structural statement hash as `axioms.lock`): it fails on a reached axiom that is not listed,
  on a changed statement or module, on a stale entry (module in the audited closure, axiom not
  reached), and on a reached axiom or a lock entry declared in a module other than `Rmcp.Types`
  or `Rmcp.Funs` (fix round 3, R2b-2; the audit rejects such a reached axiom too, so a

  a default target) are reported as not checked. The lock is the module's "reached by the audited closure" set: the
  module is recorded because the default roots do not import `Rmcp` yet, so a lock entry could
  otherwise not be told apart from a stale one.
