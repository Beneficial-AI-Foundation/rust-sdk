## Stated exceptions and review rules

- **`String` and memory.** `ok` from a `String` model means "returns, or aborts or panics for
  memory reasons": out of memory, and `RawVec::grow_amortized` requesting more than `isize::MAX`
  once the capacity exceeds `isize::MAX / 2`, are not modelled; growth of the length beyond
  `isize::MAX` bytes is `fail panic`; `push_str` of a non-UTF-8 `Str` is `fail undef`.
- **Clock.** `now_ms = ok nowMs`. Environmental assumption: `chrono::Utc::now` panics if the
  system clock is before 1970 or outside chrono's range (`chrono-0.4.45/src/offset/utc.rs`
  lines 96–98), not modelled. One constant makes every reader pure, so **no spec statement
  mentions the functions `rmcp.model.request_state.RequestStateCodec.now_ms`,
  `…RequestStateCodec.open` or `…RequestStateCodec.open_with`** (a variable named `now_ms`, such as
  the time parameter of E01 `open_authenticated_body`, is not covered; `open`/`open_with` are
  translated, not targets; `seal_with` is excluded). For this reason the draft `now_ms_spec` was
  removed in fix round 2.
- **`HashMap::get`.** The model returns the first entry with an equal key, without hashing. It is
  faithful for `Hash`/`Eq` instances that agree and do not fail; only `K = Q = String` occurs.
  **Note for S12:** `Nodup` of the keys is needed only to identify which value is returned;
  `find?` returns `some` exactly when an entry with an equal key exists, so "found" and "not
  found" facts need no `Nodup` premise (`find?_key_isSome_iff`, added in fix round 3: a value is
  found exactly when `k` is a key; `find?_key_of_not_mem`; `find?_key_of_mem` uses it to name the
  value).
- **`String` `Hash`.** Writes the bytes, then `0xff`: for `DefaultHasher`, `write_str` forwards
  (`std/src/hash/random.rs` 135–137, `core/src/hash/sip.rs` 237–239) to the override at
  `core/src/hash/sip.rs` 303–308 (`write(bytes); write_u8(0xFF)`); `write_u8` is not overridden
  (note at line 248), so it is the default `write(&[i])`. Unused by the `get` model.
- **`zeroize`.** Zeroisation on drop and the volatile writes are not modelled.
