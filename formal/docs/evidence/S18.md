## Findings

- F1 (documentation): `formal/README.md` at `5ea289a` still opens with "Status: **S03:
  toolchain only.** … there is no translation, specification or proof yet", which is stale.
  Proposed fix: update the status line to the current stage (translation, specs and proofs
  through S15) or drop the status line in favour of the plan board.
- F2 (scope of the reproduction): the toolchain and Mathlib-cache download paths of
  `aeneas-install.sh` and `lake exe cache get` were not exercised, because the user-level
  rustup, elan and `~/.cache/mathlib` caches already held the pinned artifacts. The checks
  that the selected toolchains are the pinned ones (rustc commit hash, `charon
  toolchain-version`, `lean-toolchain`, manifest commits, archive sha256) did run. Proposed
  follow-up: the CI job `lean-build.yml` (fresh runner) covers the elan and Mathlib download;
  a run with empty `RUSTUP_HOME`/`ELAN_HOME` would cover the rest if the reviewer wants it.
- F3 (dependency resolution, already documented): `Cargo.lock` is git-ignored and the translate
  script resolves dependencies afresh, so transitive dependencies other than the seven pinned
  crates follow the crates.io index at run time. This run reproduced the committed translation
  byte for byte, but a later run could resolve other versions of unpinned crates. No change
  proposed beyond what the README already states; noted for the reviewer.
- F4 (differential toolchain): `run.sh` builds `rdiff` with whatever toolchain rustup selects in
  the scratch directory (here the default `stable`, rustc 1.92.0), not a pinned one; the
  versions are recorded in `<scratch>/toolchain.txt` as documented. Proposed fix (optional,
  lead's decision): add a `rust-toolchain.toml` to `rdiff/` (copied by `run.sh`) pinning e.g.
  `1.96`, so the differential runs on the same stable compiler as the repository.
